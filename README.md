## ⚡ طرق التشغيل

### 1. التشغيل المباشر (بدون سيرفر)
افتح ملف `index.html` أو `login.html` في أي متصفح حديث (Chrome / Edge / Firefox) وسيشتغل النظام بالكامل اعتماداً على **LocalStorage**.

بيانات الدخول الافتراضية:
- **مدير النظام:** `admin` / `1234`
- **كاشير:** `cashier` / `0000`

---

### 2. التشغيل مع سيرفر PHP & MySQL
1. أنشئ قاعدة بيانات باسم `spiderx_db` واستورد ملف `sql/spiderx.sql`.
2. ضع مجلد `Spider-X` داخل سيرفر محلي (مثل XAMPP / WAMP) في المجلد `htdocs`.
3. اضبط إعدادات الاتصال في `backend/database/connection.php`.
4. حدد رابط السيرفر في `assets/js/api.js`:
   ```javascript
   API_CONFIG.baseUrl = 'http://localhost/Spider-X/backend/api/';
   ```

## 🛡️ مواصفات الصلاحيات والرقابة (Permissions & Oversight Specifications)

> تم اعتماد هذه المتطلبات ضمن مواصفات مشروع **SPIDER X – Gaming Center Management System**، لضمان أعلى معايير النزاهة المالية ومنع التلاعب داخل صالات الألعاب.

### 📋 1. جدول الإعدادات المعتمدة

| الإعداد | القرار النهائي | التفاصيل والضوابط |
| :--- | :--- | :--- |
| **الموافقة على تعديل الأسعار** | **كلمة مرور المالك** | يمنع تعديل أي سعر بيع للمنتجات أو ساعات اللعب إلا بإدخال كلمة مرور المالك. |
| **الموافقة على إلغاء الفواتير** | **كلمة مرور المالك** | إلغاء أو استرجاع أي فاتورة معتمدة يتطلب مصادقة مباشرة من المالك. |
| **مشاهدة الأرباح** | **المالك والمدير** | تقارير وصافي الأرباح متاحة للمالك والمدير فقط، وتُحجب تماماً عن الكاشير. |
| **سجل حركات الموظفين** | **تسجيل كل العمليات ومحاولات الرفض** | تتبع شامل ودقيق لكافة الحركات اليومية ومحاولات الاعتماد الفاشلة أو المرفوضة. |

---

### ⚙️ 2. قواعد التنفيذ المعتمدة (Implementation Rules)

1. **تقييد صلاحيات الكاشير:** الكاشير لا يستطيع تعديل الأسعار أو إلغاء الفواتير بمفرده تحت أي ظرف.
2. **نافذة التحقق الأمني الفوري:** عند طلب تعديل سعر أو إلغاء فاتورة، تظهر نافذة منبثقة أمنية تطلب إدخال كلمة مرور المالك لاعتماد الإجراء.
3. **التوثيق المزدوج للمسؤولية:** يُسجّل في النظام وهوية الشخص الذي طلب العملية (الكاشير) مع هوية الشخص الذي وافق عليها (المالك) بالتاريخ والوقت الدقيقين.
4. **شاملية سجل التدقيق والرقابة (Audit Trail):** تسجيل كل حركة تشغيلية أو مالية، وتشمل:
   - إنشاء الفواتير
   - تعديل الفواتير أو الأسعار
   - إلغاء واسترجاع الفواتير مع السبب
   - فتح وإغلاق جلسات البلايستيشن
   - حركات الخزنة النقدية، فتح الورديات وإغلاقها
   - محاولات الوصول والاعتماد المرفوضة (كلمة مرور خاطئة)
5. **فصل صلاحيات الإدارة:** المدير يشاهد تقارير الأرباح والمصروفات، لكنه **لا يحصل تلقائيًا** على صلاحية اعتماد العمليات المحمية (تعديل الأسعار وإلغاء الفواتير حصراً للمالك).
6. **سياسة عدم الحذف النهائي (Soft Cancellation):** لا يتم حذف الفواتير المعتمدة نهائيًا من قاعدة البيانات إطلاقاً، بل يتم تسجيل حالة الإلغاء مع توثيق السبب والشخص المعتمد.

### 🔒 3. الملاحظة الأمنية ومعايير التشفير
- كلمة مرور المالك تُخزّن بشكل مشفّر ومُجزّأ آمن (`Bcrypt` أو `Argon2` مع Salt مخصص).
- كلمة مرور المالك لا تظهر إطلاقاً في الواجهات الأمامية أو في طلبات الشبكة للكاشير أو المدير.
- جميع محاولات تخمين كلمة المرور تُسجّل تلقائياً مع عنوان IP واسم المستخدم وتاريخ المحاولة.

> **ملاحظة حالة الاعتماد:** تم اعتماد هذه المتطلبات رسمياً ضمن مواصفات المشروع، وليس معنى ذلك أنها نُفذت برمجيًا بالفعل.
